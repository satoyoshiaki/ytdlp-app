# yt版アプリ「YTDLダウンローダ」

yt-dlp のフロントエンドとして動作する単体 Android アプリ（Seal 方式）。APK のインストールのみで利用でき、解析・取得はすべて端末内の yt-dlp で行い、外部の解析 API は使わない。

本アプリは汎用のメディア取得ツールである。想定する利用場面は、自身が権利を持つコンテンツの保存、自分の投稿のバックアップ、クリエイティブ・コモンズやパブリックドメインの作品の保存、権利者の許諾がある場合など、正当な目的での利用であり、対応範囲は yt-dlp の対応状況に準じる。利用にあたっては「利用規約（利用上の注意）」を必ず確認すること。

- パッケージ名: `jp.techlab.ytdlapp.muse`
- 配布用 APK は Releases ページから取得できます（arm64-v8a のみ、debug 署名）。イメージカラーは赤（基調 **#F44336**、ステータスバー #D32F2F、チップ淡色 #FBE9E7）＋白
- ソース: 本リポジトリ直下の Gradle プロジェクト。ただしライブラリ AAR 約200MB は容量のため同梱せず、下記手順で再生成する

## 機能（完全版仕様）

- 対応範囲: yt-dlp の対応状況に準じる。アプリ内に固有のサイト名は掲げず、詳細は「情報」画面から yt-dlp 公式の対応サイト一覧ページへのリンクで示す
- URL 貼り付け＋「貼り付け」ボタン、「解析」でサムネイル・タイトル・全フォーマットを表示
- 共有メニュー連携: SEND text/plain インテントで URL を受け取り自動解析（コールドスタート時も初期化完了後に自動で解析開始）
- 画質選択: 最高画質プリセット＋高さ別プリセット＋全フォーマットの個別選択（複数選択可、映像のみ format は音声と自動マージ）
- 音声のみ抽出: ffmpeg で MP3 化
- 保存先: `/sdcard/Download/YTDL/`、ファイル名は Termux 版と同一テンプレート
  - 動画: `%(uploader_id)s_%(height)sp_%(id)s.%(ext)s`
  - MP3: `%(uploader_id)s_mp3_%(id)s.%(ext)s`
- 「情報」画面（「このアプリについて」）: 概要説明、「対応サイトはこちら」リンク（yt-dlp 公式の対応サイト一覧 https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md をブラウザで開く）、利用規約の表示
- 履歴（私のダウンロード）: サムネイル・作者・日時・サイズ表示、タップで再生、長押しで「開く／履歴だけ削除／消去（ファイルごと削除）」= 実削除対応
- yt-dlp 本体のアプリ内更新ボタン（ライブラリの STABLE チャンネル更新）
- 広告・課金・評価催促なし。日本語 UI

## 設計メモ

- 実装は Kotlin 単一ファイル `MainActivity.kt`（+ 同ファイル内 `HistoryActivity`）。画面は先行して作成したクローンアプリのデザイントークンを踏襲したコード生成 UI。
- ダウンロードはジョブ単位のプライベート一時フォルダで yt-dlp を実行し、完了後に MediaStore 経由で `Download/YTDL` へ登録（Scoped Storage 対応、権限要求なし）。
- 選択状態はキーの `Set<String>` で保持し、エンティティを Set 内で変異させない（過去の教訓どおり）。
- フォーマットの解釈（重要）: extractor によってはコーデック欄が `null` になる（ある短文投稿サービスでは http 形式の vcodec/acodec がとも null で実体は音声入り単体ファイル、同サービスの HLS 音声は acodec が null）。`none` 明示と null を区別し、null は「不明→統合ファイル扱い」として解釈する。`none` が明示されるサイトでは従来どおり映像のみ/音声のみを正しく判定する。
- ffmpeg は `FFmpeg.getInstance().init()` を明示的に呼ばないと yt-dlp に場所が渡らず、MP3 抽出・HLS・マージが全て失敗する（実機で踏んで修正済み）。

## ビルド手順（Gradle）

ビルドは、OpenJDK 17 と Android SDK を用意した Ubuntu 環境で行う。

1. OpenJDK 17、Android SDK（platforms;android-34 / build-tools;34.0.0）を用意
2. ライブラリ `youtubedl-android 0.18.1` を**ソースからビルド**する
   - 理由: JitPack は 0.15.0 以降すべてビルドエラー（0.18.1 は 2025-12-30 に Java toolchain provisioning で失敗）で AAR が取得できない。0.14.0 以下は取得可だが古い
   - `https://codeload.github.com/yausername/youtubedl-android/tar.gz/refs/tags/0.18.1` を展開し `./gradlew :common:assembleRelease :library:assembleRelease :ffmpeg:assembleRelease`
   - 生成した `common-release.aar` / `library-release.aar` / `ffmpeg-release.aar` を `app/libs/` に `common-0.18.1.aar` 等とリネームして配置し、`fileTree` ではなく個別 `files()` で参照（推移依存 appcompat 1.4.2 / core-ktx 1.8.0 / jackson-databind 2.11.1 / commons-io 2.5 / commons-compress 1.12 は Maven から別途指定）
3. アプリ本体: AGP 8.13.0 / Kotlin 2.0.21 / Gradle 8.14.3、`./gradlew :app:assembleRelease`
   - `abiFilters arm64-v8a`、`useLegacyPackaging true` + manifest `extractNativeLibs="true"`（同梱ネイティブ実行ファイルの展開に必須）
4. 署名は debug キー（個人利用の検証ビルドのため）

同梱 yt-dlp のバージョンは **2025.11.12**（ライブラリ 0.18.1 のバンドル）。アプリ内の「YT-DLPを更新」から最新化できる。

## 詰まった点と対処

- **JitPack が使えない**（0.15+ 全滅）→ ライブラリをソースからビルドして AAR をローカル配置に切替
- **git clone が pack エラーで失敗 + SSH が約28秒アイドルで切断** → tarball 取得に変更、長時間処理は全て `setsid nohup` のバックグラウンドジョブ化
- **端末が USB に見えない/インストールが USER_RESTRICTED** → 端末スリープが原因。画面を起こして（keyevent 224 + USB給電中は常時点灯）からレシピ再実行で成功
- **DownloadProgressCallback の署名**（0.18.1 では execute のコールバックはラムダ Function3）→ AAR を javap で確認して実 API に合わせて修正
- **MP3 抽出の失敗** → 原因は (1) `FFmpeg.init()` 未呼び出し (2) コーデック null の format を誤って除外し一部の形式が4件しか見えていなかった、の2点。両方修正し、デスクトップ yt-dlp 2025.11.12 の `-J` 出力と突き合わせて表示モデルを検証
- **コールドスタート共有で解析が走らない**（初期化前は早期 return していた）→ 初期化完了を待って自動解析するよう修正

## 未検証・既知の制限

- ログイン必須サイトの実ログイン検証は行っていない（仕様どおり、ログインで止まるのは可）
- 履歴サムネイルは MediaStore の生成タイミングにより表示されない場合がある（ベストエフォート）
- 署名は debug キー。ストア配布や本格運用時は正式なキーストアで再署名すること
